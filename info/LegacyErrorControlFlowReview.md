# Retiring legacy engine error control flow

Source review for JK2-TSK-24 and JK2-TSK-26 on `fix/client-options-and-server-handshake` at `969784fe`, for 1.2.11. The inventory covers eight production calls and four test calls to `Com.Error(int, String)`, all five production handlers of `longjmpException`, the 49 checks that could reach the old API through the default collision model, and the direct `Sys.Error` paths. The inventory records the original findings. Links to removed code point to its last relevant revision. The checklist tracks migration progress.

## What the review found

`Com.Error(int, String)` combines reporting, global command dispatch, and stack unwinding or JVM exit. `ERR_DISCONNECT` calls `cl_drop` and throws. `ERR_DROP` calls `sv_shutdown` and `cl_drop`, then throws. A fatal code or recursive error reaches `Sys.Error`, which calls `cl_shutdown` and exits with status 1. Cleanup therefore depends on whichever handler is registered in the process-wide command table. In the active Cake and dedicated sources, only `sv_shutdown` still has a production registration. The modern `Com.Error(String)` and `Com.Error(LogSubsystem, String)` overloads only report failures and are outside the retirement. [Legacy overload](../qcommon/src/main/java/jake2/qcommon/Com.java#L293) · [Logging overloads](../qcommon/src/main/java/jake2/qcommon/Com.java#L118) · [Command dispatch](../qcommon/src/main/java/jake2/qcommon/exec/Cmd.java#L369) · [Host command](../server/src/main/kotlin/jake2/server/ServerHost.kt#L257) · [Process exit](../qcommon/src/main/java/jake2/qcommon/sys/Sys.java#L52)

On the `legacy-jake2-client` tag, `CL.Init()` registered both client hooks. `cl_drop` called `CL.Drop()`, which disconnected the client, reset session state, and dismissed the loading plaque when applicable. The legacy Fullgame frame loop caught `longjmpException` and continued with the next frame. `cl_shutdown` called `CL.Shutdown()`, which wrote the configuration and shut down audio, input, and video. `Sys.Error` performed the process exit. In Cake, the corresponding responsibilities belong to client session cleanup and application disposal. [Legacy client guide](Legacy-client.md) · [Hook registration](https://github.com/demoth/jake2/blob/legacy-jake2-client/client/src/main/java/jake2/client/CL.java#L1532) · [Drop](https://github.com/demoth/jake2/blob/legacy-jake2-client/client/src/main/java/jake2/client/CL.java#L1551) · [Disconnect](https://github.com/demoth/jake2/blob/legacy-jake2-client/client/src/main/java/jake2/client/CL.java#L662) · [Frame loop](https://github.com/demoth/jake2/blob/legacy-jake2-client/fullgame/src/main/java/jake2/fullgame/Jake2.java#L138) · [Shutdown](https://github.com/demoth/jake2/blob/legacy-jake2-client/client/src/main/java/jake2/client/CL.java#L1501) · [Historical process exit](https://github.com/demoth/jake2/blob/legacy-jake2-client/qcommon/src/main/java/jake2/qcommon/sys/Sys.java#L48)

The biggest mismatch is Cake Fullgame. Client collision or sprite loading can reach `ERR_DROP`, which stops the registered local Host before Cake handles the exception. Cake then interprets the same exception as a local-server failure whenever embedded hosting is available, even during a remote session. Cake Client does not take that recovery branch. Prediction can also swallow the exception during inline-model lookup, after the global side effects have happened. [Default collision policy](../qcommon/src/main/java/jake2/qcommon/CM.java#L45) · [Sprite loader](https://github.com/demoth/jake2/blob/12bb073c321abda41b084edeb8b6ce27cc1c8f54/cake/core/src/main/kotlin/org/demoth/cake/assets/Sp2Loader.kt#L113) · [Cake frame handler](../cake/core/src/main/kotlin/org/demoth/cake/Cake.kt#L987) · [Prediction lookup](../cake/core/src/main/kotlin/org/demoth/cake/stages/ingame/ClientPrediction.kt#L233)

### Desktop fatal exit

Cake currently reports a frame failure to automation and rethrows it. The pinned LWJGL3 backend calls its window and listener disposal after the loop returns normally. If the loop throws, backend cleanup still runs, but the normal Cake disposal path can be skipped. For unexpected runtime failures in an active Cake application, preserve the original failure at the application boundary, report it to automation, request `Gdx.app.exit()`, and end the frame. Once the desktop loop has returned through disposal, have the launcher surface the saved cause as a failed launch. Keep ordinary quit successful. Startup failures before the loop should unwind through cleanup of resources acquired so far. This only needs one application-owned fatal outcome, with no shared severity dispatcher. ### Fatal console command removal

Removed the fatal `error` command after confirming it had no known external callers. The name now follows ordinary command lookup. `killserver`, Cake `quit`, and dedicated loop termination cover their respective lifetimes. [Former command registration](https://github.com/demoth/jake2/blob/4852574d/qcommon/src/main/java/jake2/qcommon/exec/Cmd.java#L138) · [Host stop command](../server/src/main/kotlin/jake2/server/ServerHost.kt#L251) · [Cake quit](../cake/core/src/main/kotlin/org/demoth/cake/Cake.kt#L350) · [Dedicated loop control](../dedicated/src/main/java/jake2/dedicated/Jake2Dedicated.java#L117)

`Cbuf` currently holds strings. Alias expansion puts new strings back into the queue, `wait` postpones them, and map startup can defer them. Authenticated RCON enters `Cmd` under output redirection. Cake filters server and demo stufftext before enqueueing it, and the allowlist excludes `error`. For this release, keep recovery at the existing typed operation and session entry points. If a future change grants command-specific lifecycle authority based on origin, carry the origin and owner on every queued entry through alias, script, wait, and defer. A stack-local marker would expire before postponed work runs. [Command queue and defer](../qcommon/src/main/java/jake2/qcommon/exec/Cbuf.java#L234) · [Alias expansion](../qcommon/src/main/java/jake2/qcommon/exec/Cmd.java#L316) · [RCON entry](../server/src/main/kotlin/jake2/server/ServerHost.kt#L1948) · [Cake command filter](../cake/core/src/main/kotlin/org/demoth/cake/ServerStuffTextPolicy.kt#L31)

### Remove `failureFactory`

Prefer direct exceptions. Use `IllegalArgumentException` for a caller precondition such as the CRC sequence guard and `IllegalStateException` for an unexpected invariant that should propagate. The Java sites can use `if (...) throw ...`, with no shared `check` or `require` helper needed. Give recognized collision failures a specific exception where a caller needs to distinguish them from defects. Use a nullable result when an absent value is expected, as in Cake's inline-model lookup for prediction. [CRC guard](../qcommon/src/main/java/jake2/qcommon/network/messages/client/CRC.java#L277) · [Optional prediction lookup site](../cake/core/src/main/kotlin/org/demoth/cake/stages/ingame/ClientPrediction.kt#L228)

The only production injection is `GameImportsImpl`, which already ignores the numeric severity and uses the factory to attach the owning Game. Replace that attachment at an existing Game-aware boundary. For example, the per-Game frame callback and per-client snapshot builder already know their exact Game. Catch only the collision failure there, preserve it as the cause of `GameFailure`, and let the existing Host handler stop that Game after unwinding. Apply the same rule to Game callbacks during packet handling, admission, and disconnect. Use the Game reference from the callback rather than resolving it after a failure may have changed routing.
